Applet parameters

<applet code="Scroller.class"> with five <param>

Text, both colours and the speed come from the page and none from the class. The banner asks for them as "text", "TEXTCOLOR", "bgcolor" and "Speed", so all four only arrive if the name match folds case. It also asks for "ypos", which the page does not set: that has to come back null, not empty, or the line moves to the top of the box. The applet cache is keyed by the class URL, so a second <applet> naming Scroller.class on this page would share this one's slot, its JVM and its parameters rather than being a second instance - which is why there is no side-by-side unconfigured copy here. Delete the five lines above and reload to see what this drew before getParameter existed: every default, and UNCONFIGURED on the summary line.

<object classid="java:Chime.class"> — getAudioClip

The <object> spelling, where one <param> list carries both the class name and the applet's own configuration: the element takes "code" out of it and the applet is still handed all of it, which is what a real browser does.

Three clips loaded, one of them from a URL that does not exist, a background loop started in start() and a one-shot on every click. There is no sound and there is not meant to be yet: the browser has no decoder for the era's .au, so play(), loop() and stop() record what was asked and log it. What this shows is that an applet which loads audio now runs and draws at all - before AudioClip existed it stopped dead on the class and the box stayed empty. The two base URLs it prints are getCodeBase() and getDocumentBase(), and they are different strings, which is what makes getImage(getDocumentBase(), "x.gif") resolve rather than concatenate.
